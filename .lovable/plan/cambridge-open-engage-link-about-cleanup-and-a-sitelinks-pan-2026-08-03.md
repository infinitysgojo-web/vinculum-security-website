## 4. Google sitelinks (the row-with-chevron list in search results)
Nothing is added to the website itself for this. Those rows are generated by Google, not
markup you can place — no site can force them. What the site can do is give Google every
signal it uses to pick them, and that is what this step covers:

- `SiteNavigationElement` JSON-LD on every page listing the seven public pages with the exact
  short labels that should appear as sitelinks (Doctrine, Foundations, Case Studies,
  Methodology, Vinculum Diplomacy, Glossary, About).
- Header navigation link text matched to those same labels, so the anchor text, the schema,
  and the page titles all agree — Google reads internal anchor text heavily when choosing
  sitelinks.
- Each page keeps a unique, distinct `<title>` and description (already true) and appears in
  `sitemap.xml` (verify all seven are listed).

Realistic expectation: sitelinks appear once Google is confident about the site's structure
and the site gets brand-name search traffic. The markup and labels make it possible; the
timing is Google's. After publishing, submit the sitemap in Search Console to speed it up.

## 5. Schema.org Organization and Article — what it does, and what's already there
The site already emits `Organization`, `Person`, `Book`, `BreadcrumbList`, `FAQPage`, and a
`ScholarlyArticle` on every doctrine page. So the requested markup is largely in place. What it
buys you:

- **Organization** — lets Google attach a name, logo, and official-site identity to the domain,
  which is what drives the brand icon and knowledge-panel-style result.
- **Article / ScholarlyArticle** — tells crawlers each doctrine page is an authored work with a
  headline, author, publish date, license, and DOI, so AI answers attribute the doctrine to
  James Wesley Ndua and cite this site rather than a mirror.

Two additions worth making while here:
- `SiteNavigationElement` JSON-LD listing the same rows as the sitelinks panel — the markup
  Google reads when choosing sitelinks.
- `ItemList` of the doctrine sections on the home page, reinforcing this site as the parent
  work rather than any repository deposit.
